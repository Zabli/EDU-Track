# EduTrack — User Roles and Permissions Matrix

This document provides the definitive authorization boundaries for the EduTrack platform. All operations are strictly enforced at the backend API, server action, and database (Row-Level Security) levels.

---

## 1. Role Definitions

### 1. Platform Admin (`platform_admin`)
- **Scope**: Platform-wide
- **Account Creation**: Bootstrapped via secure server-side command/secret. No public signup.
- **Capabilities**:
  - View all registered academies and pending approval requests.
  - Approve, reject, suspend, or reactivate academies.
  - Inspect system health, audit logs, and global platform usage counts.
  - Assist owners with tenant access troubleshooting.

### 2. Academy Owner / Principal (`owner`)
- **Scope**: Own academy only (`academy_id` match required)
- **Account Creation**: Secure link generated after Platform Admin approves academy application.
- **Capabilities**:
  - Full management of classes, sections, subjects, teachers, and student rosters.
  - Configure fee plans, invoices, discounts, and confirm external payment proofs.
  - Mark and audit daily student attendance registers.
  - Approve or reject student leave requests.
  - Review and act upon teacher-submitted student removal requests.
  - Manage teacher assignments, teacher attendance registers, and owner-only teacher payments.
  - Configure white-label branding (logo, colors, contact details, WhatsApp number).
  - Toggle teacher fee visibility permissions.

### 3. Teacher (`teacher`)
- **Scope**: Assigned classes, sections, and subjects within their academy
- **Account Creation**: Single-use, time-limited email invitation generated by Academy Owner.
- **Capabilities**:
  - Mark daily attendance for assigned classes/batches.
  - Enter and edit test marks for assigned classes within configured grading windows.
  - Submit student removal requests with a recorded reason.
  - View permitted student rosters for their assigned sessions.
  - View their own attendance and lecture completion records.
  - View student fee status **ONLY IF** explicitly enabled by the principal.
- **Restrictions**:
  - Cannot access owner-only finances, tuition fee ledgers, or teacher payment records.
  - Cannot access other teachers' private records or unassigned classes.
  - Cannot directly delete or deactivate students.

### 4. Student (`student`)
- **Scope**: Own student record and account only
- **Account Creation**: Matched via Academy Code + CNIC, verified email, and Principal approval if email was unverified.
- **Capabilities**:
  - View personal attendance history, rates, and absence warnings.
  - View personal test results, percentages, and teacher feedback.
  - View monthly fee status (Paid, Unpaid, Partial, Overdue) and payment instructions.
  - Submit external payment proofs (JazzCash / Easypaisa transaction ID & screenshot).
  - Submit leave requests with reason, date range, and optional proof image.
  - Contact academy administration via configured WhatsApp action.
- **Restrictions**:
  - Cannot modify official attendance, grades, fee ledgers, or profile links.
  - Cannot access another student's information or cross-academy data.

## 3. Enforcement Mechanisms

1. **Database Row-Level Security (RLS)**: Every SQL query executes with the caller's JWT context. PostgreSQL policies prevent unauthorized data leakage at the connection layer.
2. **Server-Side Authorization**: Server actions and Next.js middleware validate JWT claims, user roles, and `academy_id` matching before running logic.
3. **No Role Assumption via Frontend**: User role is derived strictly from the `profiles` and `academy_memberships` database tables, never from client-side cookies or request bodies.
